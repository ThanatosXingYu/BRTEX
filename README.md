# BRTEX

> 面向授权渗透测试的自托管多智能体平台。规划器拆解目标，执行器调用真实工具，每一条漏洞结论都与证明它的资产和 HTTP 流量绑定。

## 一、这是什么

BRTEX 是 ARTEX 的私有维护分支，宿主环境为自建 Docker + PostgreSQL，前端为 Next.js 嵌入式控制台，后端为 Go 单二进制。

它解决的问题很具体：把"人对 AI 说一句话，AI 输出一段泛泛的建议"变成"目标被拆成可执行的意图，执行器真的去跑工具，结果写回图谱，结论带着可复核的流量证据"。

## 二、与上游相比改了什么

本项目以 [Autumn-27 的 ARTEX](https://github.com/Autumn-27)（AGPL-3.0，闭源前最后的开源版本 v0.3.15 基线）为起点，并结合 [BaaRai/ARTEX](https://github.com/BaaRai/ARTEX) v0.7.0 的全部工程改进进行优化。上游的架构、流量抓包、图谱、归档等能力完整保留，BRTEX 在此基础上做了面向"长期无人值守运行 + 国内网络环境"的定向改造：

### 1. 断流不再中断任务

模型网关在上游截断连接时，原实现会直接丢弃已产生的半截输出并以错误结束。BRTEX 的 harness 层改为：

- **保留已交付内容**：已流出的正文/思考保留进历史，已执行的工具调用与结果正确配对；
- **丢弃被截断的工具调用**：参数没收全的工具块不会以 `{}` 执行；
- **注入续写指令**：要求模型从断点继续（不道歉、不复述、不重头开始），最多 3 次，且不计入轮次上限；
- **识别两类"假完成"**：网关把累计思维链镜像进正文、以及思考阶段被截断后正文为空，两者都不会被当成正常结束。

配合同 provider 断流重试 10 次（固定 10s 间隔）与熔断冷却梯度 30s→1m→1m→2m→5m→10m，长任务在抖动网络上可以自己走完。

### 2. 主 Agent 不再"说一句就停"

主 Agent 是每条人类消息一次性运行，原实现在模型只输出一段正文、不调工具时即收尾，需要人工反复发"继续"。BRTEX 增加了一层有界续跑钩子：当本轮没有任何工具调用、而 Agent 自己的 TodoWrite 计划里仍有未完成项时，注入一次"执行下一步"的阻塞消息，工具轮后自动重置配额，上限 3 次；计划已清空、或用户只是提问时完全不干预。同时修正了提示词中"汇报即收尾"的倾向。

### 3. 上下文压缩更耐故障

压缩超时从 5 分钟放宽到 10 分钟，单块压缩失败重试 3 次（每次 3 分钟上限、间隔 10s），避免一次卡顿导致整块上下文长期无法压缩。

### 4. 国内网络可用

- `web_search` 新增 **Bing（cn.bing.com）** 与 **百度** 两个无密钥、国内直连后端，设置页可直接切换；
- 镜像构建时 npm 走 npmmirror、apt 走阿里云镜像，纯源码可离线构建；
- LLM 配置中的 URL/密钥/代理会清洗不可见 Unicode 字符（零宽字符、BOM 等），这是"粘贴后一直解析失败"的常见来源。

### 5. 归档在 Windows 挂载点上可用

任务归档原实现只做目录 rename；在 Docker Desktop 的 Windows 绑定挂载上，rename 会因为文件被占用而失败，整个归档直接失败。BRTEX 增加了**日志化复制回退**：rename 失败即转为复制，中途中断可续跑或回滚；同时归档重试会清空上一次失败的残留快照文件，避免 `O_EXCL` 冲突。

### 6. MCP 与 Shell 的健壮性

- 远程/内置 MCP 在服务端只返回 `structuredContent`、没有文本块时回退读取它，不再出现"成功但空白"；
- Bash 工具在超时或取消时终止整棵进程树（Windows 用 `taskkill /T`），避免残留子进程占着任务文件导致归档失败。

### 7. 更贴合自建部署的门禁策略

上游在创建任务时强制目标不少于 80 字符且必须包含具体目标（URL/域名/IP/路径）。BRTEX 取消这两条硬限制，短目标和纯分析型目标都可直接创建；新密码最短长度维持 8 位。其余安全加固（密钥字段静态加密、会话撤销、拦截门禁、目标门禁等）全部保留。

### 8. 其他

- 版本检查指向本仓库的 Release；
- 更新策略改为本地构建或发布包升级（上游已移除页面一键自更新）；
- 修复了 Windows 绑定挂载下启动时对整棵数据目录递归 `chown` 导致的启动卡死（通过 `-exec-uid=-1` 关闭执行身份降级，与旧版行为一致）。

## 三、部署

```bash
git clone https://github.com/ThanatosXingYu/BRTEX.git
cd BRTEX
cp .env.example .env     # 至少设置 POSTGRES_PASSWORD；可选填 LLM Key
docker compose up -d --build
```

首次访问 http://localhost:8787 会进入 `/setup`，需要启动日志里打印的一次性 setup token：

```bash
docker compose logs artex | grep "Setup token"
```

镜像名为 `brtex:latest`（`./install.sh` / `./update.sh` 会本地构建）。数据持久化在 `./data` 与 `postgres` 卷上；密钥字段加密使用 `.env` 的 `ARTEX_SECRET_KEY` 或 `./keys/secret.key`，**该钥匙丢失后加密配置不可恢复，请单独备份**。
